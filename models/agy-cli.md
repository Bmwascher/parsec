# agy (the Antigravity CLI): the CLI of the Neon lane

Runs Gemini 4 Neon (`gemini-4-neon-high`) for the Neon lane's rounds (`neon.md`). Version in use: 1.5.13 (checked 2026-11-20); first written on 1.2.5 (2026-09-22). The guards themselves (the updater variable, the reviewer's settings) live in the tool; this file holds the dated facts behind them. The Gemini implementer and its build-run facts were removed on 2026-11-25 (direct build); git history keeps them.

- **The trust list is not an authorization control** (2026-09-17): nothing mechanical refuses an `--add-dir` outside it.
- **The updater** (measured 2026-09-17 on 1.2.4): the throttled auto-updater opened a console that took the foreground; `AGY_CLI_DISABLE_AUTO_UPDATE=true`, the literal `true`, disables it (at `1` it still ran). A deliberate update is `agy update` ("Update CLI", checked 2026-09-22), run by `doctor --update`.
- **A soft-denied step ends the run with exit 0** (two probes, 2026-09-22) and, on 1.2.x, an empty reply; on 1.5.13 the run ended `SUCCESS`, exit 0, with no review and a `denied_actions` key in the JSON (2026-11-20).
- **`--add-dir` needs an absolute path** (field phase 5b, 2026-09-23): given `.`, agy logged `failed to resolve --add-dir path "."`, dropped the workspace and soft-denied its reads.
- **Auth is a silent refresh** (2026-09-22) seen only in the log's `silent auth succeeded` line; the `not logged into Antigravity` lines are in every log (2026-09-24); the first run's log is the login check.
- **As a reviewer** (the Neon lane, 1.5.13, 2026-11-20): with no `--mode`, print mode runs in `auto`, which wrote a file and ran `git log`; `--mode plan` soft-denied its first command and ended `SUCCESS` with no review. Deny rules passed by `--settings` (`write_file(*)`, `command(*)`, `read_url(*)`, `execute_url(*)`, `mcp(*)`): the write and command rules came back to the model as tool errors and it went on to a verdict, the tree clean: a new file, an edit of a tracked file, a workflow script and a subagent's write were all refused. Fetch and MCP refusal is unprobed (no MCP server on the probe host).
- **A read outside the workspace was soft-denied and ended the run** with no review (2026-11-20, a rubric in the primary checkout) unless a `read_file(<path>)` allow rule in the settings named the file or a folder above it; a `%TEMP%` file was read with no rule.
- **`--output-format json`** prints one object (2026-11-20): `conversation_id`, `status`, `response`, `duration_seconds`, `num_turns`, `usage`, and `denied_actions` after a soft-deny. A run cut by `--print-timeout` has `status` `ERROR`, an `error`, `finished_reason` `print_timeout`, no `response`, exit 3. `--conversation <id>` resumes; on a resume `duration_seconds` and `usage` count the whole conversation.
- **Rule files** (2026-11-20): a `GEMINI.md` or `AGENTS.md` in the workspace reached the model as rules; an `AGENTS.md` in the folder above did not, in the one setup probed. Built-in skills (agy-customizations, antigravity-guide, run-workflow, swarm_monitor) were present in every run; no setting to turn off subagents or workflows was found (agy's docs, read 2026-11-20).
- **`agy models` showed no login state** (2026-11-20): from an empty home it still listed every model, and no logged-out agy could be made, so the pre-flight checks no login; what a logged-out run's JSON holds is UNVERIFIED. It lists Carbon only with an API key, Application Default Credentials or an enterprise gateway (agy's changelog, 1.5.5 to 1.5.8).
- **A workspace's `.agents/hooks.json` runs, and so does one in `.agent/`, `_agents/` or `_agent/`** (2026-11-20, 1.5.13, the Neon lane's exact arguments): agy loaded a tracked `.agents/hooks.json` from the reviewed tree, with the working folder inside the tree and outside it, and its `SessionStart` and `PreToolUse` hooks ran a command (a marker file was written); the deny rules held for the model, not for the hooks. A tree's `.agents/settings.json` allow list did not load; `.agents/mcp_config.json` was not probed. A second probe (2026-11-20, the same arguments, one tree per layout) found that a root `.gemini/` folder (`hooks.json`, `config/hooks.json`, `settings.json` with hooks and `mcpServers`, `mcp_config.json`, `config/mcp_config.json`) and a nested `sub/.agents/hooks.json` loaded nothing; of the layouts it tried, only the root `.agents/hooks.json` ran. agy's built-in skill `agy-customizations` names the workspace customization folder as `.agents/` "(or `.agent/`, `_agents/`, `_agent/`) at the root of your project", found by walking from the working folder up to the repository root (read 2026-11-20). Two more probes (2026-11-20, the same arguments) ran a root `.agent/hooks.json`, `_agents/hooks.json` and `_agent/hooks.json`, each; `.agent/mcp_config.json`, `.agent/config/hooks.json` and `_agents/plugins/p/hooks.json` loaded nothing. So a Neon round refuses a head whose root tracks any of the four names in any letter case, as Windows ignores case (Brandon: "Refuse such a tree"; "Refuse all four").
