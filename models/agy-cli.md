# agy (the Antigravity CLI): the CLI of the implementer and of the Neon lane

Runs Gemini 4 Hydrogen (`gemini-4-hydrogen-high`) in print mode for `build run`, and Gemini 4 Neon (`gemini-4-neon-high`) for the Neon lane's rounds (`neon.md`). Version in use: 1.5.13 (checked 2026-11-20); first written on 1.2.5 (2026-09-22). The guards themselves (the route lines, the success test, the updater variable, the reviewer's settings) live in the tool; this file holds the dated facts behind them.

- **The trust list is not an authorization control** (2026-09-17): nothing mechanical refuses an `--add-dir` outside it. The checkout is the child's working folder and its first `--add-dir`.
- **The updater** (measured 2026-09-17 on 1.2.4): the throttled auto-updater opened a console that took the foreground; `AGY_CLI_DISABLE_AUTO_UPDATE=true`, the literal `true`, disables it (at `1` it still ran). A deliberate update is `agy update` ("Update CLI", checked 2026-09-22), run by `doctor --update`.
- **Under `--mode accept-edits`, print mode ran no command and has no delete tool** (1.2.x, 2026-09-22, `gemini_probes.py`): a `RunCommand` was soft-denied. Corrected 2026-11-20: with no `--mode`, 1.5.13 runs in `auto`, which wrote a file and ran `git log`; `accept-edits` on 1.5.13 is UNMEASURED.
- **A soft-denied step ends the run with exit 0** (two probes, 2026-09-22) and, on 1.2.x, an empty reply; on 1.5.13 the run ended `SUCCESS`, exit 0, with no review and a `denied_actions` key in the JSON (2026-11-20).
- **It never reports blocked** (2026-09-22): on a checkout one commit too early it read two errors on the missing dependency, edited on and reported success. The diagnosis order is in `build`.
- **`--add-dir` needs an absolute path** (field phase 5b, 2026-09-23): given `.`, agy logged `failed to resolve --add-dir path "."`, dropped the workspace and soft-denied its reads.
- **A file in the primary checkout needs its own `--add-dir`** (KitnEssentials gk-10 task 4, gk-12 tasks 16 and 17, 2026-09-27), or, on 1.5.13, a `read_file(<path>)` allow rule in `--settings` for a read (2026-11-20, the Neon lane): each brief has a step in the local smoke file, in the primary's docs root. Read through the worktree's `dev/docs` junction, it worked (tasks 18, 19); by the primary's path, `ViewFile` was soft-denied. `build run` adds the docs root when it lies outside the checkout; on 1.2.10 (2026-09-28) a read and an edit there worked only with it. A `%TEMP%` file needs none, so a probe there tests nothing. agy's transcript (`~/.gemini/antigravity-cli/brain/<conversation>/`) or its `conversations/<conversation>.db` names the path; its log does not. In a worktree build it also read the primary's copy of the code file it was editing, which was denied (ap-17, ap-18 task 10, 2026-10-05), so the prompt names the checkout.
- **1.4.4 writes LF into CRLF files** (2026-10-23; not 1.2.10); `build run` restores CRLF.
- **New-file writes work** (`WriteToFile`, 2026-09-22); a first probe wandered to the workspace's parent when the workspace was nested under the working folder.
- **In `build run`, Gemini's tokens are recorded nowhere** the tool can read; a task's cost on this lane is time only (63 s on Task 2 of the 2026-09-22 comparison). The Neon lane's JSON has them in `usage` (2026-11-20).
- **`--mode accept-edits`**: without it the edit was soft-denied (1.2.0, 2026-09-12).
- **Auth is a silent refresh** (2026-09-22) seen only in the log's `silent auth succeeded` line; the `not logged into Antigravity` lines are in every log (2026-09-24); the first run's log is the login check.
- **In the field** (2026-09-23 to 28): print mode stopped at 5 minutes (1.2.x; corrected 2026-11-20: on 1.5.13 a 752 s print run ended `SUCCESS`); 106 of the 111 Groundhog Key runs passed first time; in all 234 field runs it tried `RunCommand` four times, each a `Select-String` search (since 0.1.18 the prompt names `grep_search`); it miscopied a value yet reported success; it adds stray blank lines.
- **Hydrogen replaced 3.8 Flash** (2026-11-20, 1.5.13, one task, the `build run` prompt): 10 of 10 passed, median 38 s; 3.8 Flash took 276 s and over, near the 5-minute stop of 1.2.x, which 1.5.13 does not have (corrected 2026-11-20: a 752 s print run ended `SUCCESS`). Without the prompt's closing text, 5 of 9 runs (3.8 Flash 3, Hydrogen 2) ended with no edits; the one logged, a 3.8 Flash run, had tried a command. Model behaviour dated earlier is 3.8 Flash's.
- **As a reviewer** (the Neon lane, 1.5.13, 2026-11-20): with no `--mode`, print mode runs in `auto`, which wrote a file and ran `git log`; `--mode plan` soft-denied its first command and ended `SUCCESS` with no review. Deny rules passed by `--settings` (`write_file(*)`, `command(*)`, `read_url(*)`, `execute_url(*)`, `mcp(*)`): the write and command rules came back to the model as tool errors and it went on to a verdict, the tree clean: a new file, an edit of a tracked file, a workflow script and a subagent's write were all refused. Fetch and MCP refusal is unprobed (no MCP server on the probe host).
- **A read outside the workspace was soft-denied and ended the run** with no review (2026-11-20, a rubric in the primary checkout) unless a `read_file(<path>)` allow rule in the settings named the file or a folder above it; a `%TEMP%` file was read with no rule.
- **`--output-format json`** prints one object (2026-11-20): `conversation_id`, `status`, `response`, `duration_seconds`, `num_turns`, `usage`, and `denied_actions` after a soft-deny. A run cut by `--print-timeout` has `status` `ERROR`, an `error`, `finished_reason` `print_timeout`, no `response`, exit 3. `--conversation <id>` resumes; on a resume `duration_seconds` and `usage` count the whole conversation.
- **Rule files** (2026-11-20): a `GEMINI.md` or `AGENTS.md` in the workspace reached the model as rules; an `AGENTS.md` in the folder above did not, in the one setup probed. Built-in skills (agy-customizations, antigravity-guide, run-workflow, swarm_monitor) were present in every run; no setting to turn off subagents or workflows was found (agy's docs, read 2026-11-20).
- **`agy models` showed no login state** (2026-11-20): from an empty home it still listed every model, and no logged-out agy could be made, so the pre-flight checks no login; what a logged-out run's JSON holds is UNVERIFIED. It lists Carbon only with an API key, Application Default Credentials or an enterprise gateway (agy's changelog, 1.5.5 to 1.5.8).
- **A workspace's `.agents/hooks.json` runs** (2026-11-20, 1.5.13, the Neon lane's exact arguments): agy loaded a tracked `.agents/hooks.json` from the reviewed tree, with the working folder inside the tree and outside it, and its `SessionStart` and `PreToolUse` hooks ran a command (a marker file was written); the deny rules held for the model, not for the hooks. A tree's `.agents/settings.json` allow list did not load; `.agents/mcp_config.json` was not probed. A second probe (2026-11-20, the same arguments, one tree per layout) found that a root `.gemini/` folder (`hooks.json`, `config/hooks.json`, `settings.json` with hooks and `mcpServers`, `mcp_config.json`, `config/mcp_config.json`) and a nested `sub/.agents/hooks.json` loaded nothing; only the root `.agents/hooks.json` ran. So a Neon round refuses a head whose root tracks `.agents` in any letter case, as Windows ignores case (Brandon: "Refuse such a tree").
