# Kimi CLI

Version in use: kimi-code 2.1.1 (2026-09-24). Written on 0.43.1 (2026-09-21); a fact marked 2.1.1 was measured again on 2026-09-24.

- **The lane home.** The lane runs with `KIMI_CODE_HOME` set to the folder named in `lanes.toml` (`home`), because the normal home's login was dead on 2026-09-21. The lane home's `config.toml` carries the model alias `kimi-code/k3` and its `default_effort`; the pre-flight checks both are present. The `credentials` folder is never opened; diagnostics print presence only. 2.1.1: `kimi doctor config` passes the lane home's file and a round runs on it.
- **`--plan` refuses `-p`** (`Cannot combine --prompt with --plan`, 2026-09-21), so a round never passes `--plan`.
- **The token lives 900 s** with a rotating refresh token and no lock file. Two rounds at once across two refreshes were measured safe on 2026-09-21 (`kimi_two_at_once.py`: 666 s and 1,113 s, two quick rounds started on an expired token, all exit 0, the credentials file rewritten once per expiry). 2.1.1: two long rounds across one refresh again exit 0 (665 s each, one rewrite); two rounds started on an expired token refreshed once, then both stopped on the weekly quota (`provider.auth_error: 403`, exit 1 in 3 s), so that case is unmeasured on 2.1.1. Not covered: three or more at once.
- **The session id is printed only at the end**, on standard error, as `To resume this session: kimi -r session_<uuid>`; the tool passes that token to `--session` as printed (0.43.1 and 2.1.1; a 2.1.1 resume answered in the same session). Whether `--session` also takes the bare uuid is unmeasured.
- **The reply is standard output**, UTF-8; thinking goes to standard error as the round runs, which is how the watcher sees life (0.43.1 and 2.1.1). Each reply block starts with `• `, which the verdict reader strips (a 2.1.1 reply of `• VERDICT: PASS` read NONE before 0.1.14).
- **A new folder does not stop a round** (2.1.1): a round in a new git folder, never trusted, ran to exit 0 with no trust question.
